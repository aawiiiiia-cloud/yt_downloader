# media-dl

## media-dl 桌面采集工具

双击 `start-collector.cmd` 启动新界面：左侧正常浏览网页，右侧解析当前内容、
选择图片或视频画质，点击“下载所选”加入下载队列。目前支持 YouTube、B站、小红书、Vimeo、抖音、Behance 和淘宝；
其他网站可浏览，采集适配后续加入。旧版 Tkinter 仍使用 `start.cmd`。

- 在左侧打开视频或笔记详情页后，点击采集面板右上角的“解析当前页面”。自动解析默认关闭，可在设置中开启并保存；升级时会关闭旧默认值一次，此后保留手动保存的选择。
- 七个站点各有自己的标签组。切站点回到该组上次页面；点击视频、笔记或作品详情链接会另开组内标签，支持 `＋` 新建和 `×` 关闭。
- 同次运行中，每个标签保留网页位置、解析结果、图片勾选和视频选项；后台页面暂停播放。重启恢复标签网址，切到标签时再加载和解析。
- B站分P或列表内容在右侧选择条目；每张图片可点击“下载”单独加入队列，也可勾选多张或全选后批量下载，保留原图顺序编号。单张下载后留在资源页，方便继续选择其他图片。
- YouTube、Vimeo 账号区域提供“Edge登录”“导入Cookies”；B站、小红书、抖音额外提供“登录”。Behance 提供网页登录和 Cookies 导入，Adobe 账号状态以左侧网页为准，不将匿名 Cookie 当作登录凭据。导入使用文件选择窗口，读取当前站点的 Netscape 格式 Cookies 文本文件（`.txt`），取消时不改变登录，原文件不修改。
- YouTube 登录统一通过 Edge 完成，验证成功后用于下载；未登录或凭据失效时禁止加入下载队列，执行前再次检查。
- Vimeo 支持公开单视频页面与播放器链接，保留未列出视频的网址访问参数。抖音支持视频详情、分享短链跳转后的详情和 `jingxuan?modal_id=…`；优先使用左侧当前视频已加载的数据，支持 MP4 视频画质；图集、直播和合集批量采集暂未接入。
- Behance 使用 `gallery-dl 1.32.17` 解析单个作品页的图片、图片组和视频模块。原图优先保存，保留 GIF 动画，支持现有格式转换；Adobe 自托管视频使用 yt-dlp 下载。外部托管视频默认跳过；点击资源页“解析外部视频”可额外识别 YouTube、Vimeo，并单独选择画质加入队列。Vimeo 优先读取左侧已加载的播放器；YouTube 仍须通过现有登录验证。网站验证或连接限制可能使部分播放器暂不可用。个人主页、收藏夹和付费附件批量下载暂未接入。
- 淘宝分组覆盖淘宝、天猫、天猫超市的单个商品图片，按主图、SKU 图、详情图分类，可单张或多选下载；按商品与分类分别保存，保留 SKU 名称清单。读取左侧已加载内容和懒加载地址，详情尚未加载时会提示展开后重试。当前已完成隔离页面与图片保存检查，真实商品样例尚未验收。详见 `.specs/TAOBAO_2026-10-25.md`。
- 视频封面通过采集端读取并缓存，支持失败重试；时长显示为 `58:47` / `1:58:47`，文件大小跟随画质更新，估算值以“约”标记。
- 图片预览使用网页展示图，另行查询原始素材大小；转换格式后的文件大小以实际保存结果为准。
- 解析、预览、大小查询、登录等待与下载处理显示转圈动画，完成或失败后停止；系统开启减少动态效果时使用静态指示。
- 界面采用深灰中性色，主按钮、选中态、勾选框、进度条和分隔条统一配色；未登录与失败信息保留红色。资源面板主下载按钮统一显示“下载所选”，处理及验证期间显示对应的进行状态。
- 右侧依次为“资源”“下载任务”“设置”三个独立面板；设置中可选择保存目录、代理、图片格式及自动解析。未保存的设置在切换面板时保留。
- 设置内默认折叠的“高级选项”提供“全局并发”（默认 5）与“单站并发”（默认 1），均可填写 1–20。每个网站使用相同的单站上限，淘宝 / 天猫 / 天猫超市共用淘宝分组名额。达到并发上限仍可继续加入下载队列，空位出现后自动执行；调低上限不打断已运行任务。分片下载参数保持原样。同一保存目录下可能写入同一作品文件的任务依次运行，避免临时文件与清单冲突。
- 站点名称紧挨“页面采集”标题，解析按钮位于同一标题区域右侧。
  未指定代理时，下载任务会按浏览器
  对该网址解析出的系统代理路线执行。
- 顶部品牌栏和底部装饰栏已移除；中间分隔条可拖动调整左右宽度并自动记住，双击恢复默认，也可用方向键微调。
- 浏览、解析与下载相互独立：关闭自动解析时，同一标签内翻短视频、跳转或刷新会保留上次已完成的解析及选择，手动点击“解析当前页面”才更新；预览与下载仍对应保留的原内容。开启自动解析时跟随新页面更新。切换标签会保留各自结果，已入队下载在关闭来源标签后仍继续执行。
- 登录信息、设置、标签网址和任务历史默认位于 `~/.media-collector/`，与旧版配置隔离。
  应用更名为 media-dl 后继续使用这个目录，无需迁移。可通过 `YT_COLLECTOR_HOME` 指定其他位置。登录凭据仅用于本机，请勿分享配置目录。

一个基于 Tkinter + yt-dlp 的多网站媒体下载工具,支持视频和小红书图文,同时提供源码版与打包版两条交付线。

## 功能特性

- **多网站下载**:支持 yt-dlp 兼容站点,包括 YouTube、Bilibili 等,支持单视频/列表
- **小红书图文**:可粘贴帖子网址或 App 整段分享文案,优先使用 `fileId`/网页资源 ID 从原始素材 CDN 下载并按顺序保存；原始源全部失效时才回退到可能带水印的网页展示图
- **三站点内置登录**:一个入口管理 YouTube、Bilibili 和小红书登录,免装 Cookie 插件
- **自动匹配凭据**:按输入网址自动使用对应站点 Cookies,混合批量任务也不会串用
- **登录状态提醒**:显示最近登录时间,超过 7 天主动建议更新;检测到失效会立即停用
- **安全更新登录**:新凭据先写临时文件并验证,成功后才原子替换;失败保留旧登录
- **简洁登录窗口**:Edge 应用模式隐藏地址栏/标签栏,保留验证码、二维码和两步验证能力
- **PO Token 完整集成**:Python 插件 + 官方 Node provider 配套打包,下载 YouTube 时自动启动、健康检查并在结束后关闭
- **实际格式日志**:下载时明确显示格式 ID、真实分辨率、帧率和编码；“最佳”不再只是抽象标签
- **JS challenge 解算**:Node.js 运行时,自动解 YouTube n-challenge 签名混淆
- **代理支持**:可选填 HTTP / SOCKS5 代理,缓解墙内直连问题
- **完整性优先**:HLS/DASH 任一分片失败即判定任务失败,不会静默生成卡顿成品
- **设置持久化**:保存目录、分辨率、Cookies、代理等重启不丢
- **环境自检自动安装**(源码版):缺 yt-dlp / Node / ffmpeg 时自动下载安装,无需管理员权限
- **PO Token 安装容错**:优先复用已编译成品；首次编译使用 npm 持久缓存和国内镜像，停滞时自动切换官方源
- **PO Token 快速启动**:安装/打包时完整核验数千个 provider 文件，日常启动只核验版本、清单和关键入口，避免企业杀毒逐文件扫描造成长时间假死
- **媒体批处理**:按已启用项目自动跳过整类媒体；通用查重覆盖图片和视频，图片近似强度可从“完全一致”滑到“宽松近似”
- **安全归档问题文件**:红色明确问题可统一移至指定目录，黄色相似图/黑边项需明确勾选；同名不覆盖，跨盘复制校验成功后才删除源文件
- **图片工具**:普通文字作为前缀自动编号，也兼容高级模板批量重命名；支持按常用比例居中裁剪副本（不改原图）
- **图文格式统一**:小红书图片可保留原格式，或统一转换为 JPG、无损 PNG、WebP；HEIC/HEIF 原图由 pillow-heif 解码
- **图片画质档位**:JPG/WebP 的 95/90/85/75 控制二次编码的细节与体积；PNG 为无损编码，因此不显示有损画质选项

## 使用方法

### 源码版(Python 3.10+；正式打包固定 Python 3.13 x64)

```bash
pip install -r requirements.txt
python yt_dlp_gui.py
```

本机的独立运行环境位于 `D:\python-envs\yt-downloader`，Pillow、pillow-heif、
dhash 和下载依赖均安装在该目录。可直接双击 `start.cmd` 启动；启动器优先使用
`YT_DOWNLOADER_PYTHON` 环境变量，未设置时使用上述 D 盘环境。
该环境的 `Scripts` 已加入用户 PATH，新终端可直接使用 `python`。
Pillow 是 Python 库，无需单独设置 `PYTHONPATH`。

首次启动会先复用项目 `build_cache/` 或旧 `dist/yt_dlp_gui/tools/` 中已有的
Node.js / ffmpeg，再自动安装确实缺失的环境。

主窗口切换到【媒体批处理】页签可扫描已有图片/视频。黑边检测只报告裁剪建议，
不会自动裁剪视频；“移动疑似文件”会在目标目录下按“图片/视频”分类保存。

### 打包版(免安装)

使用 64 位 Python 3.13 运行 `python build.py`,产出 `dist/yt_dlp_gui/` 文件夹(含便携版 node/ffmpeg/PO Token provider),整体分发即可,目标机器无需安装 Python / Node / ffmpeg。构建先在暂存目录完成并自检,失败不会删除或覆盖上一版交付物。构建会核对 Node、FFmpeg 和 provider 下载摘要，真实启动 provider 做健康检查，并生成 `dist/yt_dlp_gui.zip.sha256`。

## 测试

```bash
python -m unittest test_collector_new_sites test_yt_dlp_gui test_xhs_image_downloader test_media_batch test_collector_core -v
npm.cmd test
npm.cmd run test:electron
```

以上仅测试主项目。图片测试使用临时生成的真实 JPEG/PNG/WebP/HEIF 文件；
本机存在 ffmpeg/ffprobe 时，还会生成临时视频验证元数据、文件摘要与黑边检测。
测试不会访问真实网站或写入用户登录设置。

`npm.cmd run test:electron` 会实际启动 Electron，使用 `electron-artifacts/` 下的隔离
配置与受控页面测试左右视图、登录同步、切页防串、任务队列及重启持久化。
`npm.cmd run test:live` 是另外的只读公开页面检查，会真实联网获取元数据，不下载视频或登录账号。

## 说明

- YouTube、Bilibili、小红书凭据分别保存在用户目录下的 `.yt_dlp_gui*_cookies.txt`
- 这些文件都等同账号登录状态,仅限本机使用,不得分享或随程序分发
- 新登录凭据会在验证后原子替换，并尽量把 Windows 文件权限限制到当前用户
- YouTube 网页显示 4K 不代表旧版 yt-dlp 一定能取得 4K URL；本项目锁定 2026.08.19，并在日志以 `[格式]` 显示实际下载分辨率
- 本工具仅供学习与个人合理使用,请遵守目标平台的服务条款与当地法律法规
