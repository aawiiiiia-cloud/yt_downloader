# 下载失败原因与登录状态

2026-10-25，基于检查点 `802d4b1`。

## 下载任务

- 失败任务在卡片内显示“失败原因”与对应的中文处理建议，不再只显示笼统的“下载未完成”。取消操作保持“已取消 / 操作已取消”，包括排队时取消、执行时取消，以及取消恰好遇到网络报错。
- 分类涵盖凭证失效、需要登录、网络超时、连接失败、网站限流、验证要求、视频删除、内容不可用、访问被拒绝、下载链接过期、画质不可用、工具缺失、文件保存失败、网站服务异常和任务中断。
- 只有明确的删除/下架信息才显示视频删除。普通 404 显示内容不可用；普通 401/403 显示访问被拒绝，不据此推断凭证过期。
- 验证码、机器人验证、会员/地区/年龄限制与下载链接签名过期分别处理。网站明确拒绝登录凭据，或带有凭据的任务被明确要求重新登录，才可标记该份凭据失效。超时及文件错误的结构化证据优先，避免异常链中的旧提示覆盖真实失败原因。
- 未能确认的错误显示“原因未确定”，详情保留在可展开的任务日志中；不根据早期警告猜测失败原因。
- Python 工作进程传递有界的异常链、HTTP 状态和超时/文件错误信息，由 Electron 统一分类。日志及错误详情隐藏 Cookies、认证头、URL 凭据与签名路径/参数。
- 失败原因随任务历史保存。旧失败记录有足够错误信息时可重新归类，没有证据时维持未知；不会仅凭旧历史使当前登录失效。

## 登录状态

- 五站统一显示：无凭据为红色“未登录（建议登录）”；有凭据为“已登录”；明确失效为红色“登录凭证已失效/过期，请重新登录”。YouTube 的待验证/验证中/已验证仍在后台保留，不在状态标题中逐项展示。
- YouTube 加入下载队列前与执行时的服务端验证仍保留，Python 端仍拒绝未验证下载；界面简化不放宽登录要求。
- 失败只影响任务实际使用的站点及认证 Cookie 摘要。再次看到同一份旧凭据、刷新网页或重启不会清除失效标记；认证 Cookie 真正变化或 YouTube 成功验证后可以恢复。普通统计 Cookie 变化不恢复登录。
- 旧任务失败前会重新核对当前凭据，不能把运行期间新导入的凭据误标为失效。取消任务不会使凭据失效。
- 本机 `login-errors.json` 仅保存失效凭据的 SHA-256 摘要，不保存 Cookie 原文。该文件位于应用配置目录，不进入 Git。
