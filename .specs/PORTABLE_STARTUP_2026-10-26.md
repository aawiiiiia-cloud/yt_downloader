# Windows 整理包通用启动

公司电脑报告了 PowerShell ConstrainedLanguage 下创建 UTF8Encoding 失败，另有错误的双层代码路径、
重复 provider 全量哈希及双击 .py 关联到系统 Python 的问题。本轮只修改启动、检查和交付流程。

## 入口及恢复

- 源码 start-collector.cmd / start.cmd → distribution/start-runtime.cmd → distribution/launcher.py。
- 整理包三个 CMD 使用相同入口，内容为 ASCII、CRLF；保留中文文件夹名称，支持空格和括号。
- 启动程序/启动.py 与代码/distribution/launcher.py 共享源码，均能正确定位代码及依赖工具。
- CMD、启动.py 及旧版 yt_dlp_gui.py 双击均优先转交随包 Python 3.13 x64。源码使用指定的隔离环境，
  不向系统关联的 Python 或其他项目基础环境安装依赖。子进程环境清除外部 PYTHONHOME/PYTHONPATH/Tcl 干扰。
- 只有 Python 缺失或核心标准库不可用时调用既有 PowerShell 恢复器；其受限模式检查在任何 .NET 创建之前。
  受限时中文提示重新复制完整包或联系管理员，不清除 __PSLockdownPolicy、不改注册表或系统执行策略。
- 失败时 CMD 保留窗口；直接 .py 在交互控制台中等待回车。无窗口 pythonw 关联不保证能显示控制台。

## 检查与提速

- 移除准备阶段对 provider 的重复全量校验。2026-10-27 更新：源码和整理包日常均用关键文件校验，
  首次启动、换电脑、移动目录和缓存失效也不触发全量内容哈希；安装、修复、构建和显式环境检查仍完整核验。
- 整理包保存分模式的依赖指纹缓存，遍历依赖树的文件名、大小、mtime，不逐文件打开计算内容哈希。
- 指纹包含 Python/Node/FFmpeg/provider/Electron 依赖、机器/用户标识、绝对位置、解释器版本及启动器/锁文件元数据。
  缺文件、大小/时间变化、移动目录、更新入口或锁文件、缓存损坏、七天到期均触发重新检查。
- 指纹仅用于启动性能优化，不构成防篡改机制；相同大小和时间戳的刻意内容修改仍应通过完整检查发现。
- “检查运行环境”及 --check / --check-env 无条件完整核验一次 provider，后续诊断只复用结果。
  环境诊断子进程超时改为 180 秒，构建验收外层 240 秒。
- 快速缓存不随包作为受信结果分发；清单排除运行时缓存/锁文件。收件人或移动目录后首次重新校验。
- 下载源、固定版本、SHA-256、断点续传、失败回滚流程保持原实现；不关闭 TLS 或执行文件校验。

## 验证边界

在本机以独立测试目录模拟中文/空格/括号路径、受限 PowerShell、错误 Python 关联、缓存变化和失效。
实际整理包另验收完整环境检查及 Electron 隔离启动/重启，不读写真实账号和下载数据。
不能据此保证公司终端防护允许 Python/Electron/网络访问；此类实际拦截仍应由公司管理员核实。

本轮结果：212 项 Python 检查、100 项 JavaScript 检查、语法检查均通过；实际整理包通过 203 项
Electron 隔离检查及独立进程重启恢复。新入口完整环境检查 7.53 秒，旧版检查 6.00 秒；日常缓存命中
时准备阶段两次为 0.40 / 0.38 秒（包含解释器启动的探测进程约 0.69 / 0.67 秒）。这些是本机样本，
不代表公司电脑的耗时，也不是完整应用打开耗时。旧入口小文件备份放于依赖工具/验证结果/启动器修改前-2026-10-26。
