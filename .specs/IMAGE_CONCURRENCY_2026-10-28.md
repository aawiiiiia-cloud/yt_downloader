# 同页图片并发与下载按钮

## 行为

- 全局与单站并发设置不变。单站设为 2，同页图片 01 和 02 的单张任务可以同时运行；一个批量任务仍只占一个任务名额，内部逐张下载方式不变。
- 同一保存目录、作品及分类下，比较任务实际选中的图片编号。批量 [01, 02] 运行期间，单张 02 等待，单张 03 可以补位。不同格式也必须保护重叠编号，因为它们共用暂存路径。
- 取消中的任务在工作句柄结束前继续占位；完成、取消或失败后释放。重试仍经过同一规则。
- 较早等待的批量任务保留其选中编号的先后顺序，后来的重叠单张不会反复插队。取消等待任务立即重新调度。
- 未知或无效图片编号、视频等保留原来的整体目标保护。淘宝、天猫、天猫超市继续共用单站名额，主图 / SKU / 详情的分类目录独立。

## 按钮与文件

- 仅暂时禁用正在提交请求的那个按钮；其他单张按钮及“下载所选”可以继续提交。相同按钮收到入队结果前仍防重复点击。
- 入队成功后立即解锁，飞入动画继续播放。使用每次请求独立的标记，避免旧动画的清理操作误解锁后一次请求。
- 下载选项在点击时固定，切换解析、分类或面板后，旧请求不会覆盖新界面的选择；飞入动画结束后仍停留在当前面板，不自动跳转下载任务。
- `image_summary.py` 将小红书、Behance、淘宝、站酷共用清单改为短时间跨进程加锁、按编号合并、独立临时文件发布，防止并行任务互相覆盖记录或争抢固定 JSON 临时文件。锁只覆盖清单写入，图片网络接收不在锁内。
- Windows 命名互斥锁支持进程异常退出后恢复；等待支持取消和超时。损坏或属于其他作品的既有清单保留并报告错误。
- 沿用图片下载、原图优先、文件名、图片校验及原子替换逻辑。单应用内调度保护重叠图片；不声称协调多个应用实例同时写同一张图片，也不保证不同目录别名对应同一物理路径的协调。
