# 日常启动与缓存失效后的自检优化

## 背景

公司电脑报告：依赖齐全，输出停在 Python 库已就绪，未完成启动。当前源码与交付包确实存在
`ensure_provider(tools, strict=full_check or bundled)`：整理包缓存不命中时会全量读取 provider 文件计算摘要。
本机既有缓存命中的测试没有覆盖换机后的冷启动性能。公司具体等待时间、Defender/云壳影响仅来自用户报告，未在公司电脑复核。

## 修改

- `strict=full_check`：普通源码、整理包首次启动、换机、移动目录、缓存损坏、文件变化和七天到期后均采用关键文件快速检查。
- `--check`、`--check-env` 和“检查运行环境”仍强制完整 provider 校验；安装、修复和发布前完整校验与回滚规则保留。
- 在缓存指纹比对、Python、Node/npm、FFmpeg/FFprobe、Electron、provider 与缓存保存之前打印中文进度并立即刷新输出。
  完整 provider 校验明确提醒文件较多；不会长时间停留在上一阶段的“Python 库已就绪”。
- 缓存写入失败时显示下次仍会快速检查，不使可用依赖启动失败。不修改公司安全策略、系统环境变量或注册表。
- 保留依赖树文件名、大小、时间戳的变化检测及每模式缓存。变化后可重建缓存，不用全量内容哈希代替日常可用性检查。
  指纹遍历仍有耗时，不承诺公司电脑毫秒启动；本次没有取消文件变化检测。
- 构建器生成的使用说明同步更新，后续重新整理包也保留相同策略。

## 验证

- 22 项启动测试通过（包括六种缓存不命中情形）。测试执行真实 `prepare -> ensure_provider`，普通启动调用全量校验即失败；第一次成功保存后，第二次必须命中缓存。
- 有效缓存下显式完整检查仍执行且仅执行一次严格校验；耗时提示必须先于校验。
- 快速检查发现组件有问题进入修复时，发布前严格校验失败不能替换原文件，临时目录会清理。
- 缓存无法写入的提示、中文/空格/括号路径、受限 PowerShell 下优先随包 Python、错误 .py 关联与失败回滚检查保留。
- 根目录 11 组 Python 回归共 228 项通过；不测试独立 MissAV 或图片重命名器。
- 交付目录另运行实际随包 Python 冷/热启动准备、完整环境检查以及 CMD 入口 Electron 隔离启动和重启。结果保存在
  `依赖工具/验证结果/启动自检优化验收-2026-10-27.json`，计时为本机样本，不代表公司电脑实际耗时。
- 换机与 PowerShell 限制仅在测试子进程环境中模拟，GUI 使用隔离配置，不操作真实账户、Cookie 或下载历史。
