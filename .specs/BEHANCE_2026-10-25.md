# Behance 作品采集

2026-10-25，基于本地检查点 `aa1f8e1`。使用 `gallery-dl==1.32.17` 作为作品模块解析器，实际文件保存仍由现有队列、图片写入器与 yt-dlp 完成。

## 接入范围

- 新增 Behance 站点分组，支持组内多标签、按作品 ID 去重、手动解析结果保留和重启后网址恢复。
- 支持 `/gallery/<id>/<title>` 单个作品页；去除跟踪参数。主页、收藏夹、直播和付费附件批量下载不在本阶段范围内。
- 优先读取左侧已加载的 `beconfig-store_state` 中当前作品的媒体字段；匹配作品 ID，且不读取账号令牌或整个用户状态。缺少有效快照时由 gallery-dl 获取作品数据。
- 图片及图片组优先使用 gallery-dl 选择的源文件，另用网页版本预览、源文件查询大小。GIF 优先使用网站已有静帧预览，下载仍保留动画源；转换为 JPG/PNG/WebP 时遵循现有设置。
- Adobe 自托管视频解析封面、时长和画质，按模块标识重新取得下载数据，复用 yt-dlp。Vimeo 嵌入视频取得画质后可以直接入队，下载保留 Behance 来源页 Referer。
- YouTube 嵌入视频提供“在 YouTube 中打开视频”，进入已有分组后解析；原作品页和资源保持不变。YouTube 的登录验证、队列门禁和 Python 端检查继续保留。
- 不能取得画质的嵌入视频保留来源入口，自托管视频显示暂不可用说明；不会为它们提供虚假的最佳画质下载。其他素材继续可用。
- Behance 通过 Adobe 登录，匿名 `bcp` Cookie 不是登录证据。此阶段提供左侧网页登录与 Behance Cookies 文件导入，账号状态以网页为准；没有接入 Behance 的 Edge 账号存储同步，也没有验证真实账号的受限作品访问。

## 兼容与维护

- 依赖已安装在 `D:\python-envs\yt-downloader`，并加入 requirements、构建依赖和运行环境检查。没有复制 gallery-dl 的解析器源码；其依赖许可证为 GPL-2.0。
- 上游源码及测试：[gallery-dl](https://github.com/mikf/gallery-dl)、[Behance 解析器](https://github.com/mikf/gallery-dl/blob/master/gallery_dl/extractor/behance.py)、[Behance 测试](https://github.com/mikf/gallery-dl/blob/master/test/results/behance.py)。活跃开发已迁至 Codeberg，后续升级应同时跟进发布记录。
- 真实浏览器中的 `MediaCollectionModule.imageSizes` 可能将 `allAvailable` 数组放在尺寸对象之前；适配器整理字段顺序后再交给 1.32.17，避免上游按对象读取数组时报错。
- 允许 Adobe 正常播放器 `www-ccv.adobe.io`；解析器逐次校验请求和跳转目的地，拒绝本地地址、伪造后缀和 URL 用户名密码。外部导航只允许识别出的 YouTube/Vimeo 视频。
- 视频解析并发上限为 3，保持作品原顺序；先串行初始化 yt-dlp 插件，避免首次并发重复注册。每个解析器使用独立 Cookie 副本，不并发写回任务快照。
- 下载沿用图片完整性检查、临时文件和原子保存。选中稀疏图片编号时，进度按完成张数计算，最后为 100%。不通过小预览的比例猜测原图高度。
- 新日志统一隐藏 URL 的路径/参数和认证字段，包括 Adobe `hdnts` 签名。任务只接受主进程保存的作品快照和模块标识，网页不能传入任意流地址。

## 验收证据

- JavaScript 逻辑检查 65 项通过；Python 合并检查 172 项通过（新增 Behance 19 项）；依赖一致性检查通过。合并 Python 测试仍有此前已记录的两条 bgutil 重复注册诊断，以及 gallery-dl 上游 TLS 选项弃用提示，测试断言均通过。

- 所有网站实测使用独立配置目录，没有导入或读取用户真实登录状态。
